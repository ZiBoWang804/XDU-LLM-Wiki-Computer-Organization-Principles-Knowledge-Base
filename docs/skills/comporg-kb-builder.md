# comporg-kb-builder

## 作用

`comporg-kb-builder` 是当前《计算机组成原理》知识库的基座 skill。

它负责把原始资料变成可审、可追、可继续沉淀的 Markdown 资产，并严格遵守 `md-first` 路线。

它不再把旧的 runtime、sqlite 或地图 HTML 当作默认入口，而是围绕：

- 原始资料
- 资料整理稿
- 图像解读
- 知识点候选
- 题型候选
- 专题候选

来完成入库与沉淀。

## 适用场景

- 更新知识库
- 重建知识库
- 教材入库
- 课件入库
- 试卷入库
- MinerU 审核
- 图像解读
- 知识点沉淀
- 题型沉淀
- 发布思维导图或知识关系图

## 标准工作流

1. 读取 `AGENTS.md` 和 `CODEX.md`
2. 判断资料类型和目标层
3. 选择类型主路线
   - `PDF`：全局 `mineru` MCP
   - `Word / PPT / Office`：`markitdown`
   - `Markdown / TXT / 笔记`：直接规范化
4. 先保留 `raw_extract`
5. 主模型做准入审核
6. 对复杂图像 / 复杂表格触发视觉子代理
7. 形成 `reviewed_draft`
8. 先写入证据层
9. 再决定是否沉淀到知识点、题型、专题与反向索引
10. 发现污染、冲突、层违规或索引问题时，挂钩 `comporg-doctor`

## PDF 默认口径

当前 PDF 主路线是全局 `mineru` MCP，推荐固定口径：

- `model_version=vlm`
- `language=ch`
- `enable_formula=true`
- `enable_table=true`

同时按资料类型分流 `is_ocr`：

- 普通可编辑 PDF：`is_ocr=false`
- 扫描 / 手写 / 图片型 PDF：`is_ocr=true`

## 质量闸门

提取成功不等于允许入库。

进入证据层前必须至少检查：

- 是否存在明显乱码
- 是否只抽到模板头、标题页或空内容
- 是否出现“图片很多但正文极少”的空抽取
- 公式是否大面积损坏
- 表格是否整体散架
- 图片页的高价值信息是否已经被可靠解释

若结果不稳：

- 先重试
- 再分流到视觉子代理
- 仍不稳则 `hold_for_review`

## 关键约束

- Markdown 是唯一主知识库
- 原始资料不可静默改写
- 主模型审核先于正式入库
- 图像解释单独进入 `知识库/图像解读/`
- 资料整理稿正文必须保持干净，不保留未审乱码和错文
- 证据层先行，规范层后沉淀
- 旧脚本只可作为参考片段，不是法条
- 用户未明确要求时，不默认生成图谱或思维导图

## 子代理分工

适合使用子代理的场景：

- `vision`
  - 复杂图像、复杂表格、图片型 PDF、题目版式理解
- `architect`
  - 冲突审计、沉淀边界判断
- `verifier`
  - 入库后抽检
- `explore`
  - 只读目录定位和索引发现

## 输出要求

向用户回报时，至少说明：

- 这批资料目前到了哪一层
- 哪些内容已进入证据层
- 哪些内容被挂起待复核
- 是否触发了图像子代理
- 是否需要 `doctor` 接手治理
- 是否形成了可继续沉淀的知识点 / 题型 / 专题候选
