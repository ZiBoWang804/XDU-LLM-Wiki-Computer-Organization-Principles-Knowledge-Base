# comporg-answer

## 作用

`comporg-answer` 用于基于当前《计算机组成原理》Markdown 知识库进行答疑、作业题解答，以及“先讲知识点再做题”的混合回答。

它的核心特点不是“直接自由发挥”，而是：

- 先按 `md-first` 路线检索知识库
- 以知识点为最小读取单元
- 输出前必须做正确性检查
- 尽量贴近教材、课件、试卷和知识库模板的表达方式

## 适用场景

- 概念解释
- 定义辨析
- 课程答疑
- 完成作业题
- 按考试格式作答
- 先讲原理再给标准答案

## 触发词

- `答疑`
- `解释这个知识点`
- `完成作业题`
- `按考试格式作答`
- `先讲再做`
- `给出处`
- `补充知识库`

## 三种内部模式

### 1. concept

用于概念解释、定义说明、知识点澄清。

特点：

- 以知识点页为主
- 默认按教材表述骨架输出
- 明确列出依据与出处

### 2. homework

用于作业题、试卷题、计算题、程序分析题等标准答案生成。

特点：

- 必须输出完整标准答案
- 优先遵守题目本身要求的作答格式
- 尽量贴近 `标准化答题模板.md` 和 `代表题与标准答案.md`

### 3. hybrid

用于“先讲懂，再给答案”的场景。

特点：

- 先解释必要知识
- 再切换到正式解答
- 最后仍然必须给出可直接提交的标准答案

## 标准工作流

1. 确定是 `concept`、`homework` 还是 `hybrid`
2. 从总索引和章节 / 专题索引收缩范围
3. 优先读取知识点页
4. 必要时补读题型页、代表题、整理稿片段、图像解读
5. 组织候选答案
6. 候选答案进入统一验证缓冲层
7. 验证通过后再对外输出
8. 如发现知识缺口，先征得用户许可，再考虑写回

## 关键约束

- Markdown 是唯一主知识资产
- 不默认走旧脚本、旧 runtime、sqlite 或派生缓存
- 不应无必要全量读取整个知识库
- 每个可见答案都必须先检查正确性
- 允许多种解法，但每种解法都应有自己的知识点证据链
- 若知识库直接证据不足，也不能跳过验证
- 写回知识库前必须先获得用户许可

## 默认入口页

- `知识库/index.md`
- `知识库/知识点/index.md`
- `知识库/题型/index.md`
- `知识库/反向题型索引/index.md`
- `知识库/专题/期末重点/标准化答题模板.md`
- `知识库/专题/期末重点/高频题型覆盖表.md`
- `知识库/专题/期末重点/代表题与标准答案.md`

## 输出要求

- 使用中文
- 区分课程规范内容、依据与出处、个人内容
- 能给页码时尽量给页码
- 过程型题目要兼顾步骤说明与最终标准答案
- 对作业题、试卷题不能只讲思路，必须给最终成稿版答案

## 与其他 skill 的关系

- 与 `comporg-doctor`
  - 当回答过程中暴露出知识库错误、污染或缺口时，后续治理应交给 `comporg-doctor`
- 与 `comporg-kb-builder`
  - 当用户认可新增知识或补充答案时，后续入库与沉淀由 `comporg-kb-builder` 负责
