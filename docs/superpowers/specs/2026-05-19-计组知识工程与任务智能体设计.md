# 计组知识工程与任务智能体设计

## 1. 项目定位

本项目面向《计算机组成原理》课程，目标不是构建一个通用聊天系统，也不是单一的课程问答器，而是构建一套：

- 可纠错
- 可审计
- 可持续记忆
- 可依托知识库执行任务

的课程知识工程与任务智能体套件。

该套件围绕课程资料构建知识库基座，并在其上提供作业解答、自动组卷、自动批改、带出处答疑、知识关系网络图与思维导图等能力。

## 2. 最终交付形态

最终交付不是一个大一统产品平台，而是：

- `Skill 1 / Agent 1`：知识库构建与更新
- `Skill 2 / Agent 2`：课本风格作业解答生成与标准化书写输出
- `Skill 3 / Agent 3`：改编题目、自动组卷、参考答案生成
- `Skill 4 / Agent 4`：自动批改、评语、错题与弱项记忆
- `Skill 5 / Agent 5`：带出处答疑、例题推荐、弱项记录

补充要求：

- 知识关系网络图生成
- 思维导图生成

所有 Skill / Agent 都允许调用用户本地已有的 skills 与 MCP，但工具层不能绕过知识库优先、本地资料优先、可溯源与审核规则。

## 3. 范围与非目标

### 3.1 项目范围

- 以《计算机组成原理》课程为范围构建课程专用知识库
- 支持教材、课件、作业题、试卷以及外部补充资料的接入
- 支持多源资料冲突检测、纠错、审核与发布
- 支持 5 个 Skill / Agent 的协同工作流
- 支持共享主记忆和专属子记忆
- 支持 Quartz/Markdown 本地展示与审核
- 支持本地知识关系网络图与思维导图输出
- 支持后期增量补充课程资料
- 支持后期汇总对话与开发流程形成正式文档

### 3.2 非目标

- 不做统一云端产品平台
- 不在本次项目中直接实现跨学科即插即用泛化
- 不允许脱离知识库依据进行无依据生成
- 不把系统定义成最终权威评分者，老师可审核

## 4. 核心原则

### 4.1 知识优先级原则

- 本地教材、课件、作业题、试卷是首要依据
- 外部资料只能补缺，不能反客为主
- 外部知识可写回知识库，但必须带来源、时间、可信度与冲突状态

### 4.2 来源与结论分离原则

系统必须区分：

- `source_claim`：来源原文或来源给出的原始说法
- `accepted_knowledge`：系统当前采纳的知识结论
- `correction_record`：纠错过程与证据

原始资料永远保留，不静默覆盖；若资料存在错误，系统不得直接沿用错误知识。

### 4.3 输出治理原则

- 所有高价值输出必须先检索证据，再生成答案
- 所有输出尽量给出依据和出处
- 所有高风险输出需具备复核或审核链

### 4.4 作业解答风格原则

`Skill 2 / Agent 2` 的表达风格来源包括：

- 教材中的解题思路与叙述方式
- PPT 中的步骤展开方式
- 部分作业题已有答案或回答模式
- 教材答案的组织方式
- 知识库中已沉淀的课程知识表达方式

作业解答 Skill 必须重点强调：

- 正确性
- 课本风格一致性
- 标准化书写输出
- 引用依据完整性

## 5. 总体架构

### 5.1 六层结构

整套方案分成六层：

1. 原始资料层
2. 资料接入与提取层
3. 机器知识层
4. 可读 Wiki 层
5. Agent / Skill 层
6. 记忆与治理层

### 5.2 原始资料层

包含：

- 教材
- 课件
- 作业题
- 试卷
- 外部补充资料

其作用是提供不可轻易修改的原始证据源。

### 5.3 资料接入与提取层

默认假设资料质量不高，且格式复杂多样，需支持：

- 图片型 PDF
- 模糊图表
- 低像素图片
- 手写体
- 复杂混排
- 课件式版面

该层需完成：

- 资料分型
- 多路径提取
- OCR/PDF 抽取
- 布局识别
- 图表/手写补识别
- 提取质量评分
- 缺失与异常告警
- 人工复核入口

### 5.4 机器知识层

该层承载机器可调用的课程知识，包括：

- `source_claims`
- `accepted_knowledge`
- `correction_records`
- `knowledge_chunks`
- `concept_graph`
- `citation_map`
- `source_registry`
- 检索索引（FTS、向量、关系）

### 5.5 可读 Wiki 层

采用：

- Markdown
- Quartz

作为人类可读、可审、可展示的课程 Wiki 层。

其作用包括：

- 课程知识浏览
- 老师审核
- 本地展示与答辩
- 知识图谱与思维导图展示
- 机器知识层的可见镜像

### 5.6 Agent / Skill 层

五个 Agent 共享知识库与记忆体系，但职责分工明确。

### 5.7 记忆与治理层

包括：

- 课程知识主记忆
- 用户画像 / 错题 / 弱项主记忆
- 各 Agent 子记忆
- 审核队列
- 冲突队列
- 纠错发布机制

## 6. 5 个 Skill / Agent 设计

### 6.1 Agent 1：知识库构建与更新

职责：

- 接收原始资料与外部补充资料
- 完成解析、切块、关系链接、索引构建
- 生成可读知识页
- 生成知识关系网络图与思维导图
- 执行知识更新与纠错发布
- 对外暴露统一的 Knowledge API

### 6.2 Agent 2：课本风格作业解答

职责：

- 基于证据包完成题目分类、解题规划、答案生成、标准化书写输出
- 严格执行依据校验与格式校验
- 维护作业解答子记忆

### 6.3 Agent 3：改编题目、自动组卷、参考答案生成

职责：

- 根据知识点、题型和难度要求改编题目并自动组卷
- 生成参考答案
- 记录出题历史与覆盖情况

### 6.4 Agent 4：自动批改、评语、错题与弱项记忆

职责：

- 解析学生作答
- 生成评分建议与评语
- 写回错题与弱项记录
- 支持后期根据老师修订进行迭代更新

第一版可先采用通用普通批改口径，后续根据老师实际修改内容学习迭代。

### 6.5 Agent 5：带出处答疑、例题推荐、弱项记录

职责：

- 基于证据包回答问题
- 给出出处
- 推荐例题
- 更新弱项记录与追问链

## 7. 知识关系网络图与思维导图

这两个能力不单独升格为新的主 Skill，而归属 `Skill 1 / Agent 1` 的结构化派生输出能力。

### 7.1 知识关系网络图

来源于：

- 概念关系
- 例题关系
- 错题关系
- 章节关系

用途：

- 知识结构展示
- 错题归因
- 例题推荐
- 答辩与审核展示

### 7.2 思维导图

来源于：

- 章节结构
- 概念树
- 例题挂点

用途：

- 学习路径展示
- 章节复习导航
- 本地展示

要求：

- 必须由知识库结构化关系生成
- 必须能随知识库更新同步变化
- 不能只是模型随手绘制的静态示意图

## 8. 记忆系统设计

### 8.1 共享主记忆

包含：

- 课程知识主记忆
- 用户画像
- 错题记录
- 弱项记录
- 学习事件

### 8.2 专属子记忆

每个 Agent 保留自己的任务级子记忆，例如：

- Agent 2：高质量答案模板、风格偏好
- Agent 3：出题偏好、覆盖习惯、已出题记录
- Agent 4：评分风格、审核修正规则
- Agent 5：追问链、推荐历史、讲解偏好
- Agent 1：最近导入批次、冲突知识待审列表、失败解析记录

### 8.3 写回原则

可以直接写回：

- 学习事件
- 错题记录
- 弱项变化
- 子记忆内容

不能静默覆盖：

- 已确认高可信课程知识
- 老师审核通过的评分规则
- 已确认标准答案模板

## 9. 模型路由设计

不再默认使用本地 Ollama。  
统一采用云端模型，并按任务复杂度分配模型类别与思考强度。

### 9.1 低复杂任务

- 模型：`gpt-5.4-mini`
- 思考强度：`low / medium`

适用：

- 摘要
- 标签提取
- 引用补齐
- 格式整理
- 简单答疑
- 检索结果压缩

### 9.2 中等复杂任务

- 模型：`gpt-5.4`
- 思考强度：`medium / high`

适用：

- 解题规划
- 普通批改
- 普通组卷
- 关系抽取
- 一般答疑

### 9.3 高复杂高价值任务

- 模型：`gpt-5.4`
- 思考强度：`xhigh`

适用：

- 最终作业解答
- 课本风格高质量输出
- 复杂主观题评分建议
- 高质量参考答案生成
- 冲突知识裁定建议

## 10. 知识库工作流

统一主链：

`raw -> 分型 -> 多路径提取 -> 质量评分 -> 结构重建 -> 切块 -> 关系链接 -> 索引 -> Wiki -> Agent 调用`

### 10.1 首次建库

完成：

- source_registry 登记
- 解析清洗
- 章节/概念/题目结构化
- 切块与元数据登记
- 概念关系链接
- 双发布到索引层和 Wiki 层

### 10.2 运行时查询

任务 Agent 统一先经 Knowledge API 获取 `evidence_pack`，再调用模型执行具体任务。

### 10.3 运行时写回

任务完成后，将：

- 用户学习事件
- 错题
- 弱项
- 任务历史

按结构化方式写回共享主记忆和子记忆。

## 11. 稳健资料接入与答案复核工作流

### 11.1 资料接入工作流

必须完成：

- 资料分型
- 多路径提取
- 页级质量评分
- 结构重建
- 提取结果交叉校验
- 高风险页/块进入复核队列

### 11.2 提取效果检验

至少检查：

- 覆盖率
- 完整性
- 一致性
- 可用性

### 11.3 答案复核工作流

所有高价值输出都要经过：

1. 证据约束生成
2. 依据对齐检查
3. 独立复核
4. 风险分级

需具备以下 verifier：

- Extraction Verifier
- Knowledge Verifier
- Answer Verifier

## 12. 资料错误与纠错治理

系统必须默认考虑：

- 资料本身可能存在事实错误
- 资料可能存在排版错误
- 资料可能存在答案错误
- 资料可能存在过时内容
- 多资料之间可能存在冲突

处理原则：

- 原始资料保留
- 错误不静默继承
- 冲突显式标记
- 高风险冲突进入复核队列
- 审核后发布当前采纳结论

### 12.1 纠错流程

`发现冲突 -> 标记疑点 -> 挂起 -> 收集证据 -> 生成更正候选 -> 审核 -> 发布采纳结论`

### 12.2 数据结构

需至少维护：

- `source_claims`
- `knowledge_assertions`
- `correction_records`
- `conflict_queue`

## 13. 协作协议与接口边界

### 13.1 总规则

- Agent 1 是知识发布者
- Agent 2-5 不能绕过知识库裸生成
- 共享主记忆需经统一写回接口
- 高风险输出需可审核

### 13.2 统一接口

至少包括：

- `Knowledge API`
- `Knowledge Update API`
- `Memory API`
- `Review API`

### 13.3 写入权限

允许直接写入：

- Agent 1：知识索引、Wiki、来源登记、引用映射
- Agent 2-5：任务日志、子记忆、学习事件提案、错题/弱项写回提案

不得静默直接写入：

- 外部冲突知识的正式采纳
- 高可信课程知识覆盖
- 标准答案模板升级
- 评分规则变更

## 15. 最终验收标准

最终完成版本必须满足：

1. 5 个 Skill / Agent 全部完成
2. 5 个 Skill / Agent 各跑通 1 个完整样例
3. 作业解答 Skill 质量重点突出
4. 知识库能处理复杂、低质量、非友好资料
5. 提取质量有检测、告警与复核入口
6. 资料错误不会被系统静默继承
7. 知识关系网络图与思维导图可随知识库更新
8. Quartz Wiki 可用于本地展示与审核
9. 错题、弱项、用户画像可持续更新
10. 高风险输出具备复核或审核链

## 16. 已确认的外部条件

- 计组资料后续会继续补充
- 老师批改样例暂不强制提供，第一版采用普通通用批改规则，后期根据老师修改结果迭代
- 作业解答风格来源不依赖手写样例，而依赖教材、PPT、部分作业答案、教材答案、知识库表达
- 展示方式先采用本地展示
- 后期需将对话与开发过程汇总成正式文档文件

## 17. 后续实施建议

后续实施不以“最小版本”为目标，而以最终完成版本为目标；实施顺序只表示依赖关系和施工顺序，不表示功能降级。

建议施工顺序：

1. 知识库基座与可读 Wiki 层
2. 提取质量校验与纠错治理
3. 图谱与思维导图
4. 共享主记忆与模型路由
5. 作业解答 Skill
6. 答疑 Skill
7. 批改 Skill
8. 组卷出题 Skill
