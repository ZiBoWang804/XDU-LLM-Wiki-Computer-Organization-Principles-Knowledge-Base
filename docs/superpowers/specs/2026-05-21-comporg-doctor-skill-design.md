# comporg-doctor Skill 设计

## 1. 定位

`comporg-doctor` 是一个面向 `D:\wzb\计算机组成原理\知识库` 的知识库治理与自检 Skill。

它不直接负责答题，也不替代 `comporg-answer`。  
它的职责是：

- 巡检知识库结构与内容
- 发现错误、冲突、污染、缺口与分层违规
- 对低风险问题自动修复
- 对高风险问题生成修复申请
- 在修复后执行复检
- 将治理结果回馈给后续答题链路

为避免与全局已有的 [`doctor`](C:/Users/Zibo wang/.codex/skills/doctor/SKILL.md) 安装诊断技能撞名，本技能固定命名为：

- `comporg-doctor`

## 2. 目标

本 Skill 的目标不是“多报告问题”，而是提高后续课程答题与知识维护的稳定性。

必须达到的目标包括：

1. 发现会直接影响答题正确性的知识库问题。
2. 优先巡检最影响答题质量的层。
3. 低风险问题尽量自动修复，减少反复人工处理。
4. 高风险问题不擅自改写，保留证据并请求用户确认。
5. 对 `comporg-answer` 暴露出的结构性问题形成治理闭环。

## 3. 与现有技能的关系

### 3.1 与 `comporg-answer` 的关系

`comporg-answer` 负责：

- 检索
- 作答
- 输出前校验

`comporg-doctor` 负责：

- 治理知识库
- 修复结构性问题
- 建立勘误 / 分歧 / 修复申请
- 降低以后再次答错的概率

二者关系为：

- `comporg-answer` 负责“当前回答正确”
- `comporg-doctor` 负责“以后更不容易错”

### 3.2 与全局 `doctor` 的关系

全局现有 `doctor` Skill 负责 `oh-my-codex` 安装和环境诊断。  
`comporg-doctor` 只负责课程知识库治理。

二者不能混用，也不能共名。

## 4. 依托对象

`comporg-doctor` 依托当前 Markdown 主知识库工作，重点对象包括：

- `知识库/题型/**/*.md`
- `知识库/专题/期末重点/**/*.md`
- `知识库/知识点/**/*.md`
- `知识库/资料整理稿/**/*.md`
- `知识库/图像解读/**/*.md`
- `知识库/勘误/**/*.md`
- `知识库/分歧/**/*.md`
- `知识库/反向题型索引/**/*.md`
- `知识库/个人演化/**/*.md`

工作时必须遵守：

- `.md` 是唯一主知识库
- 原始资料不可偷偷改写
- 规范层、证据层、演化层不能混写
- 默认先索引后正文，不允许无必要地全库粗暴读取

## 5. 触发方式

`comporg-doctor` 支持两种触发方式：

### 5.1 主动触发

由用户直接触发，例如：

- 巡检知识库
- 检查这批页
- 查一下有没有错
- 治理这个知识点
- 扫一下最近补的题型页

### 5.2 被动触发

由其他 Skill 挂钩触发，尤其是 `comporg-answer`。

典型触发条件包括：

- 回答与知识点页冲突
- 用户质疑后确认原答案有误
- 同一知识点反复出错
- OCR / 整理稿噪声污染回答
- 题型页、代表题页、知识点页之间不一致

## 6. 巡检优先层级

巡检优先顺序固定为：

1. `题型页 / 代表题页 / 标准化答题模板`
2. `知识点页`
3. `资料整理稿 / 图像解读 / 勘误 / 分歧`
4. `个人演化层`

理由：

- 第一层最直接影响后续答题正确性与输出风格
- 第二层是规范层，错误影响面最大，但修订要更谨慎
- 第三层主要用于定位来源冲突和 OCR 污染
- 第四层主要用于维护用户画像与个人演化记录的整洁性

## 7. 问题分类

`comporg-doctor` 固定按以下 8 类问题分类：

### 7.1 知识冲突

例如：

- 知识点页与题型页结论不一致
- 代表题页与知识点页冲突
- 资料整理稿和当前采纳结论冲突且未进勘误 / 分歧层

### 7.2 答案错误

例如：

- 代表题答案本身有误
- 题型页中的建议作答模板含错误步骤
- 已沉淀答案与课程规范不一致

### 7.3 证据污染

例如：

- OCR 错字
- 图像误读
- 资料整理稿噪声污染后续知识抽取
- 页码 / 图表对应关系错误

### 7.4 链接 / 索引错误

例如：

- 死链
- 漏链
- 题型页新增后反向题型索引未同步
- 索引页入口遗漏

### 7.5 分层违规

例如：

- 个人理解写入知识点正文
- 规范层与演化层混写
- 证据层内容被误写成课程结论

### 7.6 格式 / 模板偏差

例如：

- 未按已固定答题模板维护
- 未按课件风格要求维护高频题型呈现
- 题型页与期末重点页风格断裂

### 7.7 画像 / 演化异常

例如：

- 用户薄弱点挂错知识点
- 感悟 / 理解写乱
- 演化层条目组织混乱

### 7.8 覆盖缺口

例如：

- 高频知识点缺少稳定规范页
- 高频题型没有代表题
- 证据层明显缺口导致答题不稳

## 8. 处置策略

采用以下总策略：

- `低风险自动修，其他先申请许可`

### 8.1 可自动修复的问题

默认可自动修复：

- 死链
- 漏链
- 反向题型索引漏同步
- 演化层格式不一致
- 纯模板偏差
- 显然无争议的索引结构错误

### 8.2 需先申请许可的问题

默认必须先申请许可：

- 知识结论修订
- 标准答案修订
- 勘误结论建立或改写
- 分歧结论改判
- 代表题答案改判
- 规范层正文改动

### 8.3 许可申请内容

对于不可自动修的问题，至少要明确说明：

1. 涉及哪一类问题
2. 涉及哪些文件
3. 发现依据是什么
4. 准备怎么改
5. 为什么不能自动改

## 9. 工作流

`comporg-doctor` 的内部流程固定为：

1. 确定巡检范围
2. 读取相关索引和目标页
3. 归类问题
4. 进行低风险自动修复
5. 对高风险问题生成修复申请
6. 执行修后复检
7. 输出巡检报告
8. 必要时回写易错点、勘误候选、覆盖缺口候选

### 9.1 巡检范围确定

巡检范围可以是：

- 全库指定层
- 某个专题
- 某个知识点
- 某组题型页
- 某批新增 / 最近修改页

### 9.2 读取原则

仍然遵守 md-first：

- 先读索引
- 再进入目标页
- 必要时回读证据层

不默认全量加载整个知识库。

### 9.3 复检原则

凡是自动修过的地方，都必须复检：

- 链接是否恢复
- 索引是否可达
- 关系是否同步
- 风格是否符合模板

## 10. 输出格式

巡检结果固定输出为四段：

### 10.1 问题摘要

包含：

- 发现了几类问题
- 哪些是高风险
- 哪些已自动修复

### 10.2 问题清单

每条至少包含：

- 问题类型
- 涉及文件
- 风险等级
- 依据
- 建议动作

### 10.3 自动修复记录

包含：

- 改了什么
- 为什么能自动改
- 改后是否复检通过

### 10.4 待确认的修复申请

包含：

- 哪些不能自动改
- 准备怎么改
- 为什么要用户确认

## 11. 与答题链路的挂钩

`comporg-answer` 若发现以下情况，应挂钩 `comporg-doctor`：

- 知识点页与答案冲突
- 用户质疑后确认答案确有错误
- 多次出现同一知识点错误
- 证据层噪声影响回答
- 某类题型长期缺代表题 / 规范表达

在 `comporg-answer` 内部，可记录：

- `doctor_hook_required = true`

并把问题转交给 `comporg-doctor` 做后续治理。

## 12. 回写对象

`comporg-doctor` 可以回写或建议回写的对象包括：

- `反向题型索引`
- `题型页`
- `期末重点专题页`
- `勘误页`
- `分歧页`
- `个人演化页`

对 `知识点正文` 的改写要格外谨慎，默认视为高风险动作。

## 13. 非目标与禁止事项

当前 `comporg-doctor` 不负责：

- 直接代替答题 Skill 回答问题
- 重建旧运行时数据库体系
- 在无证据情况下改写规范层结论

明确禁止：

- 把个人风格偏好改写成课程规范结论
- 跳过证据层直接改判知识结论
- 未经许可改写高风险内容
- 为了“修快一点”而破坏现有索引结构

**把课程知识库里的结构性问题、答案问题、证据污染和分层违规尽早发现并治理掉，从而让后续答题更稳定、更可信。**
