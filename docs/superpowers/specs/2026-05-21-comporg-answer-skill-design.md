# comporg-answer Skill 设计

## 1. 定位

`comporg-answer` 是一个依托当前《计算机组成原理》Obsidian Markdown 知识库工作的统一答题 Skill。

它不再拆成“答疑 skill”和“作业 skill”两个独立入口，而是提供一个统一入口，在内部完成：

- 提问意图判定
- 知识库分层检索
- 候选答案生成
- 缓冲校验
- 正式输出
- 补库候选与用户画像更新

它面向的主任务是：

- 纯知识性答疑
- 作业题 / 试题正式解答
- 先解释必要知识、再给标准答案的混合请求

## 2. 设计目标

本 Skill 必须同时满足以下目标：

1. 优先依托现有 Markdown 主知识库回答，不回到旧的运行时 / 数据库优先方案。
2. 题目解答类请求最终必须输出一份完整、规范、可提交的标准答案。
3. 题目中若已明确规定回答格式，必须优先遵守题面要求。
4. 所有输出在对用户可见前，都必须先经过正确性检查。
5. 若发现知识库缺口，不直接静默补写；先生成补库候选，再请求用户许可。
6. 若用户质疑答案，先重新自检，再解释，并更新薄弱点画像。

## 3. 依托知识库

Skill 以以下 Markdown 主库为核心依托：

- `知识库/index.md`
- `知识库/章节/**/*.md`
- `知识库/专题/**/*.md`
- `知识库/知识点/**/*.md`
- `知识库/题型/**/*.md`
- `知识库/反向题型索引/**/*.md`
- `知识库/专题/期末重点/标准化答题模板.md`
- `知识库/专题/期末重点/高频题型覆盖表.md`
- `知识库/专题/期末重点/代表题与标准答案.md`
- `知识库/资料整理稿/**/*.md`
- `知识库/图像解读/**/*.md`
- `知识库/勘误/**/*.md`
- `知识库/分歧/**/*.md`
- `知识库/个人演化/**/*.md`

主规则：

- `.md` 是唯一主知识库
- 知识点页是规范层
- 资料整理稿和图像解读是证据层
- 个人理解和用户画像先进入演化层
- 不全库粗暴读取，必须按索引逐层进入

补充规则：

- 不额外新开“题型视觉索引主层”
- 与题型相关的视觉模板能力，默认并入题型层内部扩展页

## 4. 模式设计

### 4.1 `concept`

用于：

- 概念
- 定义
- 原理
- 区别
- 原因解释
- 知识点联系

输出重点：

- 课程规范内容
- 依据与出处
- 对应知识点
- 必要时推荐例题或题型

### 4.2 `homework`

用于：

- 作业题
- 试卷题
- 计算题
- 程序分析题
- 结构设计题
- 综合题

输出重点：

- 完整标准答案
- 与题面要求一致的格式
- 必要的分步推导、原理阐述、知识点剖析、易错点提醒

### 4.3 `hybrid`

用于：

- 题目本身可作答，但前置知识不解释会导致跳步
- 用户明确要求“先讲一下再做”
- 需要先补关键原理再给标准答案

输出重点：

- 先用短段解释关键知识
- 再输出完整标准答案
- 解释层不能取代最终正式答案

## 5. 模式路由规则

### 5.1 路由判断

先判断请求主目标：

- 若用户主要在问“是什么 / 为什么 / 怎么理解 / 区别是什么”，路由到 `concept`
- 若用户给出完整题目、参数、程序、公式、表格或明确要求“求 / 算 / 分析 / 写出 / 设计”，路由到 `homework`
- 若用户同时包含“先讲”与“再答”，或不解释会直接影响作答质量，路由到 `hybrid`

### 5.2 用户显式覆盖

用户可直接覆盖自动路由：

- “只解释，不做题”
- “直接按考试格式作答”
- “先讲一下再写完整答案”

### 5.3 模型自修正

若初判模式与后续发现不一致，允许切换：

- `concept -> homework`
- `homework -> hybrid`
- `hybrid -> homework`

但切换必须服从“题目解答类请求最终必须给完整标准答案”的总规则。

## 6. 检索协议

### 6.1 固定读取顺序

默认读取顺序必须是：

1. `知识库/index.md`
2. 对应 `章节索引` 或 `专题索引`
3. 对应 `知识点页`
4. 需要题型骨架时读 `题型页`
5. 需要“某知识点常怎么考”时读 `反向题型索引`
6. 需要标准作答风格时读 `标准化答题模板` 与 `代表题与标准答案`
7. 仍不足时再回读 `资料整理稿`、`图像解读`、`勘误`、`分歧`

### 6.2 知识点抽取规则

- 最小检索单元是“知识点”
- 第一轮先提取 `1~3 个核心知识点`
- 再按需要补充 `0~2 个支撑知识点`
- 禁止无约束地拉取大量无关知识点

### 6.3 题型层使用规则

- 题目解答类请求，若能判定题型，应优先进入题型页
- 若题型页已有高频作答骨架、失分点、代表题入口，应优先复用
- 反向题型索引用于从知识点反查典型考法，不作为知识点正文替代物
- 若某题型已建立内部扩展页，应按以下顺序读取：
  1. `QT-xxx.md` 题型主页面
  2. `QT-xxx-作答母版.md`
  3. `QT-xxx-视觉索引.md`
- `QT-xxx-视觉索引.md` 与 `QT-xxx-作答母版.md` 仍属于题型层，不是独立平行主层

### 6.4 模板强化前置步骤

对题目解答类请求，在正式生成答案前，默认增加一个“模板强化前置步骤”。

流程：

1. 先判定题型
2. 再锁定相关知识点
3. 再读取该题型的：
   - 题型主页面
   - 作答母版页
   - 视觉索引页
   - 必要时对应图片解读索引
4. 先恢复这类题“答案长相”和版式特征
5. 再正式生成标准答案

目的：

- 不是先想答案、再生硬套模板
- 而是先恢复题型模板风格，再按这个风格出答案

## 7. 输出生成规则

### 7.1 题目解答类总规则

凡是题目解答类请求，无论是 `homework` 还是 `hybrid`，最终都必须输出一份完整、规范、可提交的标准答案。

原理解释、知识点剖析、易错点提醒都属于辅助层，不能替代最终答案。

### 7.2 回答格式优先级

格式优先级固定为：

1. 题目中明确要求的回答格式
2. 教材 / 试卷 / 课程常用标准写法
3. 题型层中沉淀出的标准作答骨架
4. 题型层内部的作答母版与视觉索引所体现的版式特征
5. Skill 默认模板

### 7.3 标准答案骨架

若题面未指定更具体格式，则题目解答默认按以下骨架整理：

1. 题意
2. 已知
3. 分析
4. 分步推导
5. 结果
6. 结论

### 7.4 题型专项约束

- 程序功能题：必须拆成“初始化 / 循环主体 / 结束或输出”
- 微操作题：必须拆成“取指 / 取数或形成地址 / 执行 / 写回”
- `Booth 乘法 / 交替除法`：遵守 `标准化答题模板.md` 中的专门约束，包括“必须把每一步按表格形式写出”

### 7.5 多解输出规则

允许多个解法输出，但每个解法都必须有独立知识点依据链。

规则：

- 若只检索到一种方法所需依据，只输出一种
- 若多种方法都能被知识库支撑，可输出多解
- 若存在课程资料中更常见的主解，优先将其列为首解
- 仅由模型发散想到、但知识库未支撑的方法，不作为正式多解输出

## 8. 全局缓冲校验层

### 8.1 全覆盖原则

所有输出，在对用户可见之前，都必须进入“缓冲校验层”。

不是只有知识库证据不足时才校验，而是：

- `E1 原题原解命中` 要校验
- `E2 同题型迁移` 要校验
- `E3 知识点拼接` 要校验
- `E4 知识库缺口` 要校验，而且校验最重

### 8.2 校验内容

每次至少检查：

1. 课程依据检查
2. 过程正确性检查
3. 结果回代 / 反推检查
4. 格式要求检查
5. 易错点检查

必要时再做：

- 独立二次推理复核
- 联网搜索复核

### 8.3 错误修正规则

若缓冲层发现答案有误：

1. 必须先修正
2. 修正后重新校验
3. 通过后才能输出
4. 同时记录该次错误涉及的知识点、来源页与易错点

## 9. 证据状态

Skill 内部维护四种证据状态：

- `E1 原题原解命中`
- `E2 同题型高相似迁移`
- `E3 知识点拼接作答`
- `E4 知识库缺口处理态`

注意：

- 证据状态只影响“依据强弱、校验重点、后续治理动作”
- 不影响“全部都必须先校验再输出”的全局规则

## 10. 知识库缺口与补库许可

### 10.1 缺口处理

若发现知识库直接证据不足：

1. 允许模型先推导候选答案
2. 但候选答案不能立刻对外输出
3. 必须先进入缓冲校验层
4. 校验通过后方可输出
5. 同时生成补库候选

### 10.2 补库许可规则

默认不自动写回知识库。

发现缺口时，应先用固定模板向用户申请补库许可，至少说明：

- 缺的是哪个知识点或题型
- 准备新增到哪一层
- 依据来自哪道题、哪份答案或哪份资料
- 写回后会新增哪些正向链接

只有用户明确同意后，才允许写回。

## 11. 用户认可答案后的沉淀规则

若用户给出作业题，且对当前答案表示认可，或提供老师 / 标准答案，可进入“题目沉淀流程”。

允许沉淀到：

- 对应题型页
- 代表题与标准答案页
- 资料整理稿补充
- 必要的个人演化页

关联规则：

- 题目层维护正向关联
- 指向 `tested_points` / `used_points`
- 不在知识点正文手写反向关系
- 反向关系仍由反向题型索引和 backlinks 派生

## 12. 输出附加信息

在知识库依据充分且能获取对应字段时，输出中允许附：

- 来源素材
- 对应页数 / 页码
- 涉及知识点
- 对应题型
- 考频
- 难度
- 易错点

字段约束：

- `考频`：`高频 / 中频 / 低频 / 未知`
- `难度`：`基础 / 中等 / 综合 / 高风险易错`

若当前知识库中无明确页数或难度记录：

- 可以标注“当前页码未精确标注”
- 可以标注“难度待补”
- 不允许编造页码或统计

## 13. 用户质疑后的闭环

若用户对回答产生质疑或疑问，流程必须是：

1. 重新进入缓冲校验层
2. 再次独立自检
3. 若原答案有误，先修正
4. 再进行答疑解释
5. 记录用户薄弱点、疑惑点、未掌握知识点
6. 针对性推荐练习与复习建议

原则：

- 先确认答案正确，再解释原因
- 不能跳过自检直接辩解

## 14. 用户画像规则

用户画像默认按“知识点聚合”维护，不按对话流水散写。

每个聚合条目可包含：

- 常见疑惑
- 用户薄弱点
- 易混淆概念
- 推荐练习方向
- 最近一次暴露时间
- 最近相关题目或对话来源

此外，若用户在讨论或答题后给出了自己的：

- 理解
- 类比
- 感悟
- 个人化总结

也应一并记录到该知识点对应的个人演化条目中，并与“课程规范内容”明确分层。

写入规则：

- 用户薄弱点、疑惑点、易混淆点属于“画像信息”
- 用户自己的理解、类比、感悟属于“个人演化内容”
- 二者都默认写入演化层，不直接写入知识点正文
- 个人化内容不得伪装成课程标准结论

## 15. `doctor` 治理钩子

后续将建设专门的知识库治理自检 Skill：`doctor`。

当前 `comporg-answer` 需预留以下触发条件：

- 发现资料冲突
- 发现代表题答案与知识点不一致
- 发现用户质疑后确实存在答错
- 发现同一知识点高频出错
- 发现 OCR / 整理稿噪声污染到规范回答

在 `doctor` Skill 建立前，可先内部记录：

- `doctor_hook_required = true`

## 16. 非目标与禁止事项

本 Skill 当前不负责：

- 统一总控所有计组 Skill
- 组卷、批改的完整工作流
- 自动无许可写回知识库

明确禁止：

- 全量粗读整个知识库
- 绕开知识点层自由发挥
- 把低证据答案伪装成原题标准答案
- 把个人理解直接写进知识点正文
- 默认回到旧的数据库 / 运行时实现路线
- 为了“先答出来”而跳过缓冲校验层
