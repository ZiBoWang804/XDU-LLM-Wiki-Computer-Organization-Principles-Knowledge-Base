# comporg-grading Skill 设计

## 1. 定位

`comporg-grading` 是一个依托当前《计算机组成原理》 Markdown 知识库的自动批改 Skill。

它不负责知识库构建，也不直接负责标准答案生成，而是负责：

- 识别题目与学生作答
- 对照知识库标准依据进行细粒度给分
- 生成评语
- 产出错因、弱项与练习建议
- 为后续画像和治理生成写回候选

## 2. 目标

第一版的核心目标不是“自动定最终分且不可更改”，而是：

1. 批改结果可追溯
2. 给分依据可解释
3. 老师后续容易复核和修改
4. 批改过程能沉淀错题和薄弱点
5. 最终输出前必须经过大模型审核层

## 3. 依托对象

`comporg-grading` 依托以下 Markdown 主库工作：

- `知识库/题型/**/*.md`
- `知识库/知识点/**/*.md`
- `知识库/专题/期末重点/标准化答题模板.md`
- `知识库/专题/期末重点/高频题型覆盖表.md`
- `知识库/专题/期末重点/代表题与标准答案.md`
- `知识库/资料整理稿/**/*.md`
- `知识库/图像解读/**/*.md`
- `知识库/个人演化/**/*.md`

工作时必须遵守：

- `.md` 是唯一主知识库
- 规范层、证据层、演化层不能混写
- 先索引后正文，不允许无必要地全库粗暴读取

## 4. 判分粒度

第一版固定采用：

- `细粒度给分`

即按以下粒度逐项批改：

- 小问
- 步骤
- 知识点

输出中必须同时写出：

- 得分点
- 扣分点
- 总评

## 5. 判分依据优先级

批改依据优先级固定为：

1. 题目本身给出的标准或要求
2. 知识库中的代表题答案、题型模板、标准化答题模板
3. 知识点页与证据层
4. 若仍不足，再由模型给出合理评分建议

这意味着：

- 不允许先凭模型印象打分
- 必须先吃本地标准依据

## 6. 评分策略

固定采用以下规则：

1. 结果对但关键步骤缺失：给部分分，不给满分
2. 思路对但算错 / 写错中间量：保留过程分
3. 只写结论、无依据且该题型本应写步骤：严格扣步骤分
4. 格式不符合题目明确要求：记录为格式问题，但默认不单独扣分
5. 学生写法和标准答案不同，但知识上成立：允许按等价解给分
6. 证据不足无法确定是否应给分：标成“待老师确认”

## 7. 输出结构

批改结果固定分为 6 段：

### 7.1 题目与作答识别

包含：

- 当前批改的是哪道题
- 有哪些小问
- 学生实际答了哪些内容

### 7.2 标准依据

包含：

- 使用了哪些知识点
- 使用了哪些题型页、代表题、模板页
- 需要时说明证据层补充

### 7.3 逐项评分

按：

- 小问
- 步骤
- 知识点

逐项给分，并写清：

- 得分点
- 扣分点

### 7.4 总分与分数建议

包含：

- 建议总分
- 各部分累计得分
- 若依据不足，明确标注为“建议分”

### 7.5 评语

面向学生的简洁评语。

### 7.6 错因与弱项写回候选

包含：

- 主要错因
- 薄弱知识点
- 推荐练习方向

## 8. 最终输出前的大模型审核层

这是本 Skill 的硬规则。

`comporg-grading` 不是：

- 识别
- 给分
- 输出

而是：

1. 识别题目与学生作答
2. 检索标准依据
3. 细粒度给分
4. 生成评语与错因分析
5. **进入大模型审核层**
6. 若审核发现问题，回退修正
7. 审核通过后才正式输出

### 8.1 审核层检查项

至少检查：

1. 判分一致性
2. 依据一致性
3. 等价解漏判
4. 步骤分合理性
5. 评语一致性
6. 高风险项拦截

### 8.2 判分一致性

检查：

- 分步得分之和是否等于建议总分
- 得分点和扣分点是否自洽
- 有没有“前面说对、后面又扣错分”的矛盾

### 8.3 依据一致性

检查：

- 批改依据是否真来自题面、题型页、代表题、知识点页
- 有没有把不稳定推断伪装成标准依据

### 8.4 等价解漏判

检查：

- 学生写法虽不同，但知识上是否成立
- 是否错误地把“写法不同”当成“答案错误”

### 8.5 步骤分合理性

检查：

- 本应给过程分的地方是否扣太狠
- 本应扣步骤分的地方是否放太松

### 8.6 评语一致性

检查：

- 分数、扣分点、评语语气是否一致
- 是否存在“分很低但评语像全对”或反过来的情况

### 8.7 高风险项拦截

若出现以下情况，应优先标成“待老师确认”：

- 证据不足
- 难以判断部分分
- 图像识别不稳
- 学生答案字迹或结构模糊

不允许在高不确定场景下强行定死分数。

### 8.8 审核后的处理规则

- 审核通过：正式输出
- 审核不通过：退回批改层修正后再审
- 若多轮后仍无法稳定判断：输出“建议评分 + 待老师确认项”

## 9. 写回策略

### 9.1 错题与弱项

默认自动生成写回候选：

- 先不直接写入规范层
- 先进入个人演化 / 学习画像候选

### 9.2 评语风格

若后续老师对评语做了修订，应保留为：

- 评分风格修正样本

用于后续迭代评分口径。

### 9.3 高风险写回

以下默认需先申请许可：

- 升级为代表题
- 修改标准答案
- 修改评分规则
- 改动知识点规范表达

## 10. 与其他技能的关系

### 10.1 与 `comporg-answer`

`comporg-answer` 负责：

- 标准答案生成
- 答疑

`comporg-grading` 负责：

- 学生答案批改
- 评分建议
- 评语
- 错因分析

### 10.2 与 `comporg-doctor`

`comporg-doctor` 负责：

- 知识库治理
- 发现结构性问题
- 修复知识库

当 `comporg-grading` 批改中发现：

- 标准答案本身可能错
- 题型模板与知识点冲突
- 高频扣分点可能来自知识库污染

应生成 `doctor_hook_required` 候选。

## 11. 工作流

`comporg-grading` 的内部流程固定为：

1. 识别题目与学生作答
2. 锁定题型和相关知识点
3. 检索标准依据
4. 逐项打分
5. 生成评语与错因分析
6. 进入大模型审核层
7. 若通过，正式输出
8. 生成错题 / 弱项 / 风格写回候选

## 12. 非目标与禁止事项

当前 `comporg-grading` 不负责：

- 直接替老师做最终不可更改判分
- 在无依据情况下自创评分标准
- 直接修改知识点规范层

明确禁止：

- 不经审核直接输出批改结论
- 因格式问题默认单独扣分
- 因写法不同直接否定等价正确解
- 未经许可改动高风险评分规则或标准答案
