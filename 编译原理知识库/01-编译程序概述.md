# 编译程序概述

> **所属章节**：第1章 概论
> **核心问题**：什么是编译程序？编译过程有哪些阶段？各阶段任务是什么？

---

## 1.1 翻译程序、编译程序与解释程序

### 基本概念

- **翻译程序**：将一种语言（源语言）的程序翻译成另一种与之等价的语言（目标语言）的程序
- **编译程序**：将**高级语言**（如C、Java）翻译成**低级语言**（汇编语言或机器语言）的翻译程序
- **解释程序**：边翻译边执行，**不产生目标代码**，直接执行源程序的语义
- **汇编程序**：将**汇编语言**翻译成**机器语言**

### 编译与解释的区别

| 特征 | 编译方式 | 解释方式 |
|------|---------|---------|
| 目标代码 | 生成目标代码 | 不生成目标代码 |
| 执行效率 | 高（编译后可多次运行） | 低（每次重新翻译） |
| 错误发现 | 编译时一次性检查 | 运行到错误处才报错 |
| 代表语言 | C、C++、Pascal | BASIC、Python（部分） |

> [!tip] 记忆口诀
> 编译：先翻译再执行（一次编译，多次运行）
> 解释：边翻译边执行（不生成目标代码）

## 1.2 编译过程的六个阶段

```mermaid
graph LR
    A[源程序] --> B[词法分析]
    B --> C[语法分析]
    C --> D[语义分析]
    D --> E[中间代码生成]
    E --> F[代码优化]
    F --> G[目标代码生成]
    G --> H[目标程序]
```

### 各阶段任务

| 阶段 | 任务 | 输入 | 输出 |
|------|------|------|------|
| **词法分析** | 识别单词（标识符、关键字、运算符等） | 源程序字符流 | 单词符号（token）序列 |
| **语法分析** | 分析语法结构，检查语法正确性 | 单词符号序列 | 语法树/推导树 |
| **语义分析** | 检查语义正确性（类型检查等） | 语法树 | 带语义信息的语法树 |
| **中间代码生成** | 生成与机器无关的中间表示 | 语法树 | 中间代码（如四元式、三元式） |
| **代码优化** | 改进中间代码，提高运行效率 | 中间代码 | 优化后的中间代码 |
| **目标代码生成** | 生成目标机器代码 | 优化后的中间代码 | 目标程序（汇编/机器码） |

### 表格处理和出错处理

编译过程中还伴有**表格处理**和**出错处理**两个辅助部分：
- **表格处理**：登记源程序的各类信息（符号表等）
- **出错处理**：报告错误类型和位置

---

## 1.3 编译前端与后端

| 部分 | 包含阶段 | 特点 |
|------|---------|------|
| **前端** | 词法分析、语法分析、语义分析、中间代码生成 | 与源语言相关，与目标机器无关 |
| **后端** | 代码优化、目标代码生成 | 与目标机器相关，与源语言无关 |

### 遍（Pass）

- **遍**：对源程序或其中间结果从头到尾扫描一遍，完成规定任务
- 由于内存限制，编译程序的多个阶段可组合成**若干遍**
- 每遍的工作往往是**顺序**进行的

---

## 1.4 错误类型与检测阶段

| 错误类型 | 检测阶段 | 示例 |
|---------|---------|------|
| 词法错误 | 词法分析 | 在数中出现非数字字符 |
| 语法错误 | 语法分析 | else 没有匹配的 if |
| 语义错误 | 语义分析 | 使用的函数没有定义、类型不匹配 |
| 运行时错误 | 代码生成/运行时 | 数组下标越界、除以零 |

> [!warning] 常考
> "else 没有匹配的 if" 属于**语法分析**阶段报错；"数组下标越界"属于**运行时**（代码生成阶段要生成检查代码）

## 1.5 T型图

T型图用于描述编译程序的实现方式，三个角分别表示：
- **S**：源语言
- **T**：目标语言
- **I**：实现语言（用什么语言编写编译器）

```
      S（源语言）
     /          \
    /            \
   T（目标语言）---I（实现语言）
```

> 例如：用C语言编写的将Pascal翻译为x86汇编的编译器，T型图为 (Pascal, x86汇编, C)

## 1.6 编译程序的开发技术

1. **自编译方式**：先用汇编语言写一个简单编译器，再用它编译更复杂的编译器
2. **移植方式**：将一种语言的编译器从一台机器移植到另一台机器
3. **自动生成**：利用编译器构造工具（如LEX、YACC）自动生成

## 1.7 软件分类与编译理论的地位

### 软件分类层次

```
软件
├── 系统软件（编译系统、操作系统等）
│   └── 语言处理系统（编译程序、解释程序等）
└── 应用软件
```

- **系统软件**：居于计算机系统中最靠近硬件的一层，与具体应用领域无关
- **语言处理系统**：把软件语言书写的各种程序处理成可在计算机上执行的程序
- **软件语言**：需求定义语言、功能性语言、设计性语言、程序设计语言、文档语言

### 编译理论与其他课程的关系

- **离散数学** → 形式语言与自动机 → **编译理论**基础
- **数据结构** → 编译理论的素材
- **操作系统** → 编译理论的控制对象

### 编译理论的应用

| 技术 | 应用场景 |
|------|---------|
| 有穷状态技术 | 文本编辑、模式识别 |
| 上下文无关文法 | 情报检索、程序校验 |
| 语法制导翻译 | 文本处理程序 |
| 代码优化技术 | 非结构化→结构化程序转换 |

## 1.8 编译程序的生成方式

### 六种生成方式

1. **直接用机器语言**编写编译程序
2. **用汇编语言**编写编译程序
3. **高级语言编写**（自展方式）
4. **编译工具**自动生成
5. **移植**：将A机器上的编译程序搬到B机器上
6. **交叉编译**：A机器上的编译程序产生B机器上的目标代码

### 自展方式（Bootstrapping）详细过程

```
步骤1: 用汇编语言实现C子集编译程序(P0)
步骤2: 用P0编译C子集源程序 → 得到P1(汇编)
步骤3: 汇编程序处理P1 → 得到P2(可直接运行)
步骤4: 用C子集编制C语言编译程序(P3)
步骤5: 用P2编译P3 → 得到P4(C语言编译器)
```

> 核心思想：先造简单编译工具，再用这个工具编译编译器自己（滚雪球）

### 常用构造工具

| 工具 | 功能 |
|------|------|
| **LEX / FLEX** | 自动产生词法分析器（扫描器） |
| **YACC / BISON** | 自动产生语法分析器 |
