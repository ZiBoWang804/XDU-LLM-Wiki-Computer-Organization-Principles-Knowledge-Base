# 带成功开销的流水线性能

## 定义

带成功开销的流水线性能，是指在理想流水线之外，再把分支成功、控制相关停顿等额外代价计入后，对实际性能做修正分析。教材在 `6.3.6` 中用分支成功后的停顿开销说明：理想 `CPI` 很容易被控制相关显著拉高。

## 课程资料中的表述

- 假设理想情况下 `CPI = 1`，教材进一步讨论带分支成功开销时的流水线性能。
- 若某流水线在分支成功后会导致若干个时钟周期的停顿，那么这些停顿会直接推高实际 `CPI`。
- 教材明确指出：控制相关对流水线性能造成的损失远比数据相关要大得多。

## 结构 / 规则 / 公式

- 本节的中心意思是：
  - 理想情况下可以先设 `CPI = 1`
  - 但一旦把分支成功后的停顿开销算进去，实际 `CPI` 会明显增大
  - 因而实际加速比会明显低于理想加速比

- 教材给出的可靠示例是：
  - 若某流水线在分支成功后会停顿 `3` 个时钟周期
  - 分支指令频度为 `30%`
  - 理想 `CPI = 1`
  - 则可近似理解为

$$
\mathrm { CPI } _ { \mathrm { 实际 } } \approx 1 + 0.3 \times 3 \approx 2
$$

- 这个例子说明：实际加速比只能达到理想加速比的大约 `50%`。

- 因此，本节可以稳定抽出的结论是：
  - 分支成功开销会直接拉高实际 `CPI`
  - 分支频度越高、每次成功后的停顿越长，流水线性能损失越明显
  - 控制相关造成的性能损失通常大于数据相关

## 易混点 / 易错点

- 不要把理想 `CPI = 1` 当成实际流水线长期都能达到的结果。
- 分支成功开销不是“偶尔的小修正”，在分支频繁的程序里会显著吞掉加速收益。
- 控制相关带来的损失往往比数据相关更重，不能只盯数据相关优化。

## 常见关联场景

- 估计分支成功停顿对流水线性能的影响。
- 解释为什么“理想加速比”和“实际加速比”差距会很大。
- 为后续讨论分支预测、延迟分支等优化技术提供性能背景。
