# 工作原理

## 定义

cache 的工作原理建立在程序及数据访问的局部性原理之上。教材在 `7.3.1` 中先说明位置和构成，再说明命中、未命中以及地址变换的基本过程。

## 课程资料中的表述

- 教材先用局部性原理解释 cache 存在的依据：在较短时间间隔内，程序集中在某一较小的内存地址空间执行，数据访问也存在类似局部性。
- 基于这种局部性，在 CPU 和主存之间设置一种容量比较小而速度高的存储器，把当前正在执行的程序和正在访问的数据放在其中，CPU 便可直接访问这部分高速小容量存储器。
- 教材把 cache 的构成概括为三部分：替换管理模块、由相联存储器构成的存储表、小容量高速度存储器。
- 当 CPU 读主存指令或数据时，地址同时送往主存和相联存储表。若在相联存储表中检索到要读写的信息就在 cache 中，则通过相联存储表把主存地址转换为 cache 地址，从 cache 中读出信息，这称为“命中”。
- 若在相联存储表中未检索到要读写的信息，则称为“未命中”。这时 CPU 用主存读周期从主存中读出指令或数据，同时把包括该信息在内的一块主存内容调入 cache，并替换其中某一块。

## 结构 / 规则 / 公式

- 工作基础：程序局部性和数据局部性。
- 基本组成：替换管理模块、相联存储表、高速小容量存储器。
- 基本流程：地址同时加到主存和相联存储表上，先判断命中与否，再决定是地址变换后从 cache 读出，还是从主存读出并调块替换。
- 教材特别强调：cache 中的内容与主存相应部分的内容完全一样，是主存内容的复制；整个 cache 系统都是由硬件实现的。

## 易混点 / 易错点

- “命中”不是简单地看地址是否访问过，而是看相联存储表中能否检索到对应主存块信息。
- cache 中保存的是主存内容的复制，不是另一套独立的数据版本。
- 本页讨论的是总体工作原理，具体地址映射方式和替换算法要分别看后续知识点。
