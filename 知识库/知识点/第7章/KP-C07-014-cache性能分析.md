# cache性能分析

## 定义

教材在 `7.3.4` 中从加速比、成本以及命中率与容量的关系三个方面分析 cache 的性能，重点是说明设置 cache 后为什么能“使访存速度接近 cache、而成本接近主存”。

## 课程资料中的表述

- 教材把性能分析的重点放在“加速比”上，因为设置 cache 的主要目的就在于提高存储系统速度，同时兼顾价格。
- 在命中率较高时，cache 系统的平均访问周期接近 cache 的访问周期；块越大，命中率可能提高，但替换开销也随之增大。
- 从成本角度看，虽然 cache 的单位价格高于主存，但只要容量远小于主存，整个存储系统的平均价格仍接近主存。
- 从容量与命中率的关系看，cache 容量较小时，命中率随容量增加上升很快；容量增加到一定程度后，再增加容量对命中率的贡献就很有限。

## 结构 / 规则 / 公式

- 平均访问周期：

$$
\mathrm { T } = \mathrm { H } \bullet \mathrm { T _ { c } } + ( 1 - \mathrm { H } ) \bullet ( \mathrm { T _ { c } } + \mathrm { T _ { x } } )\tag{7-1}
$$

- 其中，`Tx` 为块的调入时间或替换开销。若 cache 以一个字或一个字节为一块，则 `Tx = Tm`；若以 `n` 个字或 `n` 个字节为一块，则 `Tx = nTm`。
- 加速比：

$$
\mathsf { S } _ { \mathtt { P } } = \mathrm { T } _ { \mathtt { M } } / \mathrm { T }\tag{7-2}
$$

- 平均成本：

$$
\mathrm { C } = ( \mathrm { C } 1 \mathrm { S } 1 + \mathrm { C } 2 \mathrm { S } 2 ) / ( \mathrm { S } 1 + \mathrm { S } 2 )\tag{7-3}
$$

- 命中率与容量关系的经验近似：

$$
\mathrm { H } = 1 - \mathrm { S } ^ { - 0 . 5 }\tag{7-4}
$$

- 教材给出的例子中，`Tm = 100ns`、`Tc = 10ns` 时，平均访问周期可达 `11ns`，相应加速比为 `100/11 = 9.9`。

## 易混点 / 易错点

- 块变大并不等于性能一定提高，因为命中率提高的同时替换开销也会增大。
- 命中率越高，加速比越大，但其上限只能接近 `Tm/Tc`，并不是无限增大。
- cache 容量增加对命中率的改善不是线性的，后期会明显变缓。

## 常见关联场景

- 计算平均访问周期和加速比。
- 讨论块大小、容量和成本之间的折中。
- 说明图7-37为什么表现为“先快后缓”的关系曲线。
