# 替换算法

## 定义

当要访问的主存块未在 cache 中，即发生未命中时，需要把主存块调入 cache，并替换 cache 中某一块。教材把决定“替换哪一块”的规则称为替换算法。

## 课程资料中的表述

- 教材把常见替换算法分为随机替换、先进先出、近期最少使用、最不经常使用和最优替换五类。
- 随机替换算法用随机函数发生器产生需替换的块号，因不考虑历史和使用情况，命中率较低，教材明确指出“现已不再使用”。
- FIFO 只考虑装入先后，不考虑当前是否仍在频繁使用，因此命中率也不高。
- LRU 利用计数器反映近期使用情况，符合程序和数据访问的局部性原理，所以教材认为其命中率较前两种算法高。
- LFU 统计一段时间内访问次数最少的块，但由于计数周期限定在两次替换之间，不能完全反映近期访问情况。
- OTP 需要事先知道未来访问情况，虽然必然最佳，但教材明确指出这种方法并不实用，只能作为衡量其他算法的标准。

## 结构 / 规则 / 公式

- RAND：随机产生待替换块号。
- FIFO：替换最先装入 cache 的块。
- LRU：每块设置计数器，命中块清0，其他块加1；替换计数值最大的块。
- LFU：每块设置计数器，命中块加1；替换计数值最小的块，并在替换时把各块计数器清0。
- OTP：先记录后判断，第二次执行时按未来最晚再用的块进行替换。
- 教材示例中，访问序列为 `P2、P3、P2、P1、P5、P2、P4、P5、P3、P2、P5、P2`，图7-36给出的命中率分别为：FIFO `3/12=25%`，LRU `5/12=42%`，OTP `6/12=50%`。

## 易混点 / 易错点

- OTP 是理论上的最优算法，不是实际系统中可直接按教材方法实现的通用算法。
- LRU 和 LFU 的区别在于：LRU看“最近是否常用”，LFU看“一段时间内总共用了多少次”。
- FIFO 只看先后次序，不看当前是否仍在使用，这正是它命中率不高的重要原因。

## 常见关联场景

- 比较不同替换算法的命中率。
- 分析为什么某种替换策略更符合局部性原理。
