# 数据的浮点表示

## 定义

数据的浮点表示是把数写成“尾数 × 基值的阶码次幂”的形式，从而在有限字长下表示更大的数值范围。教材在 `2.1.2` 中先说明一般浮点形式，再讨论规格化、机器零以及 IEEE754 的基本格式。

## 课程资料中的表述

- 在前一小节中,已经详细地讨论了有关定点数的编码问题，本小节将说明浮点数的表示方法。有关定点数和浮点数的运算将在下一章讨论。
- 实际上，计算机中处理的数不一定是纯小数或纯整数，而且有些数据的数值范围相差很
- 大（如电子的质量 $9 \times 1 0 ^ { - 2 8 }$ 克，太阳的质量 $2 \times 1 0 ^ { 3 3 }$ 克)，它们都不能直接用定点小数或定点整数表示，但均可用浮点数表示。浮点数即小数点的位置可以浮动的数，如
- $$
- 3 5 2 . 4 7 = 3 . 5 2 4 7 \times 1 0 ^ { 2 } = 3 5 2 4 . 7 \times 1 0 ^ { - 1 } = 0 . 3 5 2 4 7 \times 1 0 ^ { 3 }
- $$
- 显然，这里小数点的位置是变化的，但因为分别乘上了不同的10的幂方，故其值不变。浮点数被表示成一般形式为
- $$

## 结构 / 规则 / 公式

- 浮点数的一般形式为：

$$
\mathbf { F } = \mathbf { M } \times \mathbf { R } ^ { \mathbf { E } }
$$

其中：
  - `M` 为尾数
  - `R` 为基值
  - `E` 为阶码

- 当基值为 `2` 时，教材把浮点表示写成二进制形式来讨论。浮点数的优点是表示范围大于同字长定点数，但代价是结构更复杂、运算步骤更多。

- 规格化的目的，是让尾数的绝对值限制在规定范围内，以充分利用尾数字段表示有效数字。
  - 当尾数 `M >= 0` 且采用补码表示时，规格化形式应为：

$$
\mathbf { M } = 0 . 1XXXX\cdots X\tag{2-14}
$$

  - 当尾数 `M < 0` 时，规格化形式应为：

$$
\mathbf { M } = 1 . 0XXXX\cdots X\tag{2-15}
$$

- 基值为 `2` 时，规格化尾数的绝对值应在 `1/2 ~ 1` 之间。

- 规格化过程分为：
  - 左规：尾数左移一位，阶码减 `1`
  - 右规：尾数右移一位，阶码加 `1`

- 教材特别指出“机器零”：
  - 当尾数为 `0` 时，不论阶码为何值，机器都把该浮点数当作 `0`
  - 若阶码用移码、尾数用补码表示，则全零形式有利于简化判零电路

- IEEE754 的基本思想是：
  - 用 1 位表示符号
  - 用移码表示指数
  - 用尾数字段表示有效数字
  - 规格化时最高有效位 `1` 隐含存放，不在尾数字段中显式写出

- 教材还从四个方面比较了定点数和浮点数：
  - 浮点数表示范围更大
  - 规格化浮点数精度更高
  - 浮点运算步骤更多、速度更慢、硬件更复杂
  - 浮点数通常只在上溢时才需要停止运算处理

## 易混点 / 易错点

- “浮点数”不是简单地把小数点随便移动，而是移动尾数时必须同步修改阶码，保证数值不变。
- 规格化要求的是尾数满足规定形式，不是只要写成 `M×2^E` 就自动规格化了。
- 浮点数的溢出主要看阶码范围，不是像定点数那样直接看数值本身是否超界。
- IEEE754 的尾数最高有效位在规格化时通常是隐含的，不能机械地把尾数字段当成完整尾数。

## 常见关联场景

- 把真值写成规格化浮点表示。
- 根据阶码位数、尾数位数和编码方式求表示范围。
- 为后续浮点加减、乘除、IEEE754 编码题提供前置表示规则。
