# 中断的基本概念

## 定义

在 CPU 执行程序过程中，由于 CPU 内部或外部某种事件发生，强迫 CPU 暂时停止正在执行的程序而转向处理该事件，处理结束后又回到原来中止处继续执行，这一过程称为中断。

## 课程资料中的表述

- 教材先区分中断源：由处理机内部产生的称为内部中断源，由处理机外部设备产生的称为外部中断源。
- 对外部中断源而言，事件发生后要通过 CPU 的中断请求输入引线提出请求。教材特别强调，有效请求必须保持到被 CPU 发现，并且在 CPU 响应后要及时撤销。
- 教材以外部可屏蔽中断 `INTR` 为例说明中断的一般过程，认为无论哪种 CPU 都存在一个类似的基本过程。

## 结构 / 规则 / 公式

- 中断的一般过程按先后顺序包括：
  - 中断请求
  - 中断承认
  - 断点保护
  - 中断源识别
  - 对中断源服务
  - 断点恢复和中断返回
- CPU 承认 `INTR` 请求必须满足四个条件：
  - 一条指令执行结束
  - CPU 处于开中断状态，即 `IF=1`
  - 没有 `RESET`、`HOLD` 和 `NMI` 等更高优先级请求
  - `STI`、`IRET` 等特殊指令执行完后，还需再执行一条指令
- 断点保护分两部分：一部分由 CPU 硬件自动完成，另一部分由程序员在中断服务程序中利用指令完成。
- 中断源识别常用两种方法：
  - 软件查询
  - 中断向量法
- 中断返回由 `IRET` 指令完成，它负责恢复 CPU 在断点保护时自动保护的内容。

## 易混点 / 易错点

- 断点保护不是全部都由 CPU 自动完成，程序员还必须保护本中断服务程序中要用到的寄存器。
- `IRET` 恢复的是 CPU 自动保护的那部分内容；程序员自己压栈保存的内容，仍要由程序员自己恢复。
- “中断向量”是中断服务程序入口地址，不等于“中断向量码”；二者在后续通过中断向量表建立联系。

## 常见关联场景

- 说明中断的一般过程。
- 回答“为什么请求信号必须保持到被 CPU 发现”“为什么响应后要撤销请求”等问题。
- 解释软件查询法与中断向量法的区别。
