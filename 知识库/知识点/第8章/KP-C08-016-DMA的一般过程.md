# DMA的一般过程

## 定义

DMA 的一般过程，描述的是 `DMAC` 在被 CPU 初始化后，如何提出 DMA 请求、如何接管系统总线、如何完成数据传送、以及如何把总线交还 CPU。

## 课程资料中的表述

- 教材以 `DMAC` 为实现 DMA 的核心器件来说明一般过程，并以 Intel 8237 作为例子。
- `DMAC` 既可以完成单字节传送，也可以完成整块数据传送，还可以支持请求传送和多通道优先级控制。
- 教材特别强调：`DMAC` 在不同阶段扮演两种不同角色。
  - CPU 执行程序并初始化它时，它只是系统总线上的一个接口
  - DMA 请求得到响应后，它变成系统总线的控制器
- 整个 DMA 过程的关键，是 CPU 何时让出总线、DMAC 何时控制总线、以及传送结束后如何恢复 CPU 正常工作。

## 结构 / 规则 / 公式

- 教材给出的 DMA 一般过程：
  1. 外设向 `DMAC` 发出 DMA 请求
  2. `DMAC` 通过 `HOLD` 向 CPU 提出 DMA 请求
  3. CPU 完成当前总线周期后作出响应，并把地址、数据、控制总线置高阻，同时送出 `HLDA`
  4. `DMAC` 在 CPU 放弃总线后向外设应答，并开始控制总线
  5. `DMAC` 送出地址和控制信号，实现外设与内存或内存与内存的数据传送
  6. 传送结束后，`DMAC` 撤销对 CPU 的 DMA 请求，CPU 重新取得总线控制权
- 教材还特别指出：CPU 放弃总线控制权时，必须配合 `HLDA` 等信号使总线形成电路置高阻，避免总线竞争。

## 易混点 / 易错点

- DMA 请求不是一来 CPU 就立刻停下，而是要等 CPU 完成当前总线周期。
- CPU 放弃控制权不仅仅是“不再发指令”，而是要真正把总线置高阻。
- `DMAC` 初始化阶段与传送阶段的身份不同，这是理解 DMA 的关键。
