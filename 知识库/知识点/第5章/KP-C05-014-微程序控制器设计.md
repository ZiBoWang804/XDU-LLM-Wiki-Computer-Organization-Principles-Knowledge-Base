# 微程序控制器设计

## 定义

微程序控制器设计是把一条机器指令的执行过程分解为若干微操作，再把这些微操作对应的微指令顺序存入控制存储器，由微程序按序读出执行，从而完成指令控制。教材在 `5.4.4` 中既说明其构成，也说明微指令编码与微程序编排的基本思路。

## 课程资料中的表述

- 在上面的讨论中，规定CPU执行指令的时序分为三个机器周期，每个机器周期分为 4个节拍，每个节拍为一个时钟周期。这是一种分析和解决问题的方法。
- 完全可以将一条指令的执行过程顺序地由多个步骤(或称为状态)来完成。也就是将每一条指令的执行过程分解为若干个状态，每一状态的操作完成时根据情况启动下一个状态。当一条指令最后一个状态完成时，再启动执行下一条指令的起始状态。
- 首先，写出5.4.3小节中两条指令的过程。
- ① ADD BX,[DI]
- a) $\mathrm { P C } _ { \mathrm { o u t } } , \mathrm { A R } _ { \mathrm { i n } }$
- b） $\mathrm { A R { } A B , R D , P C { + } 1 }$
- c） $\mathrm { M D { } D B , D R _ { i n } }$
- d) $\mathrm { D R } _ { \mathrm { o u t } } , \mathrm { I R } _ { \mathrm { i n } }$

## 结构 / 规则 / 公式

- 基本概念链条：
  - 微操作：更细粒度的基本操作
  - 微命令：控制完成微操作的命令
  - 微指令：能够产生一个或多个微命令的二进制编码
  - 微程序：完成一条机器指令功能的一段微指令序列
- 微程序控制器的核心组成包括：
  - 控制存储器 `CM`：存放全部微程序，教材默认它采用只读存储器
  - 微地址形成电路：依据操作码、寻址方式、状态信号和后继地址控制字段形成微地址
  - 微地址寄存器 `μAR`：保存当前微地址
  - 微指令寄存器 `μIR`：保存当前微指令
- 后继地址控制的基本方式包括：
  - 顺序执行：下一微地址为当前微地址加 `1`
  - 无条件转移：下一微地址由地址字段给出
  - 其他转移方式：由控制字段和状态条件共同决定
- 微指令控制域编码遵循两个基本原则：
  - 互斥信号放在同一字段
  - 相容信号放在不同字段
- 字段译码法中，每个字段都必须保留一个“无效/空操作”编码。因此：
  - 若某字段有 `m` 位，则该字段只能提供 `2^m - 1` 个有效控制信号编码
  - 不能把“有 `k` 个互斥微命令”简单按 `2^m >= k` 计算，必须按 `2^m - 1 >= k` 计算
- 教材在取指微程序段中还明确说明：
  - `AC = 0` 表示顺序执行
  - 当后继地址不用时，地址字段可以全为 `0`
  - 控制域字段为 `0` 表示空操作

## 易混点 / 易错点

- 不要把“机器指令”“微指令”“微程序”混为一层：机器指令由一段微程序实现，而微程序由多条微指令组成。
- 字段译码法中必须给每个字段预留全零空操作状态，所以字段可用编码数是 `2^m - 1`，不是 `2^m`。
- 看到 `AC=0`、地址字段全零时，不能误以为地址字段“无意义”；这里表示的是顺序执行且当前不使用转移地址。
- 微程序控制器的优势是易于修改和扩充，缺点是速度通常慢于硬布线控制器。

## 常见关联场景

- 解释微操作、微命令、微指令和微程序之间的层次关系。
- 设计微指令格式、次地址位数和控制存储器容量。
- 比较微程序控制器与硬布线控制器的实现特点。
