# CPU的部件设计

## 定义

CPU 的部件设计是指在已经确定内部结构、指令系统、寻址方式和指令执行过程之后，对构成 CPU 的各个硬件部件进行具体实现设计。教材在 `5.4` 中先回顾 ALU、移位寄存器、寄存器、计数器等熟悉部件，再把重点放在控制器设计上。

## 课程资料中的表述

- 在本节之前，已经决定了CPU的内部结构，设计了CPU的指令系统及其寻址方式，并对指令执行过程进行了详细分析。经过前面的一系列工作，在此基础上可以对构成CPU的部件进行具体设计。在这节里，将简单说明前面及前期课程已学过的部件，将重点放在控制器的设计上。

## 结构 / 规则 / 公式

- 教材给出的设计前提是：
  - CPU 内部结构已经确定
  - 指令系统及寻址方式已经设计完成
  - 指令执行过程已经做了详细分析

- 在这个前提下，CPU 的部件设计主要包括：
  - 算术逻辑单元 `ALU`
  - 具有移位功能的暂存器 `T`
  - 一般寄存器与带三态输出的寄存器
  - 程序计数器 `PC`、堆栈指示器 `SP` 等可逆计数器类部件
  - 控制器

- 教材对本节的重心安排很明确：
  - 熟悉部件只作回顾
  - 真正重点放在控制器设计

- 设计控制器前，必须把指令执行分解为微操作，再把微操作对应到控制信号与时序节拍上。后续组合逻辑控制器和微程序控制器的设计，都建立在这一层分析之上。

## 易混点 / 易错点

- 这节不是重新介绍 ALU、寄存器的基本原理，而是把它们放回 CPU 整体设计场景中。
- 不要把“部件设计”和“控制器设计”割裂开；教材明确把控制器作为 CPU 部件设计的重点。
- 若前面的指令执行过程分析不完整，后面的部件设计尤其是控制器设计就无法落地。

## 常见关联场景

- 解释为什么微操作流程题和控制信号题会回到 CPU 部件设计。
- 作为组合逻辑控制器、微程序控制器两类设计的总入口。
- 回答“为什么先分析执行过程，再设计控制器”的前置问题。
