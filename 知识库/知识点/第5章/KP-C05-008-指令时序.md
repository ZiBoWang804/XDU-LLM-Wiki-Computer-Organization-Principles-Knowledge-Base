# 指令时序

## 定义

指令时序是指CPU执行一条指令时，各个时间层次和阶段的先后关系。教材在 `5.3.1` 中通过“指令周期、机器周期、时钟周期”的分层，把复杂的指令执行过程拆成可分析、可设计的时序单元。

## 课程资料中的表述

- CPU从头到尾执行一条指令所用的时间称为指令周期。
- 不同指令的功能不同，执行时间会有所不同，因此不同指令的指令周期不一样。
- 为了降低分析难度，教材把CPU通过系统总线对内存的一次读或写操作定义为一个机器周期。
- 一条指令的执行可分为三个大的步骤：取指令操作码、取操作数和执行指令，并把这些步骤看作机器周期。

## 结构 / 规则 / 公式

- 指令周期：CPU从开始到结束执行一条指令所需的时间。
- 机器周期：CPU通过系统总线对内存进行一次读或写操作所需的时间，也有资料称为CPU周期或总线周期。
- 时钟周期：更细的基本时序单位，用来进一步分解机器周期。
- 教材给出的分析框架是：
  1. 每条指令先经历取指令操作码周期
  2. 若指令有操作数，则再进入取操作数周期
  3. 最后进入执行周期
- 在这套设计中：
  - 每个机器周期结束都要查询DMA请求
  - 一条指令执行结束后，要先查DMA，再查中断
  - DMA优先级高于中断

## 易混点 / 易错点

- 机器周期不是整条指令的总时间，而是指令周期中的一个组成阶段。
- 取指令操作码周期对所有指令相同，但取操作数周期和执行周期并不相同。
- 分析时序时不要漏掉DMA / 中断查询这一层，它会影响后续控制器设计。

## 常见关联场景

- 区分“指令周期 / 机器周期 / 时钟周期”。
- 说明题型里为什么总要先写取指的统一过程。
- 作为微操作流程展开和控制器设计的时间骨架。
