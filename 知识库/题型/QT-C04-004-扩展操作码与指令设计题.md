# QT-C04-004 扩展操作码与指令设计题

## 题型定义

围绕定长指令字中的地址字段划分、扩展操作码逐层“让位”分配和指令条数计算展开的设计题。Huffman 编码与平均码长比较属于本页覆盖的次型问法，但不是主型。

## 常见问法

- 已知指令字长和地址字段位数，给定双操作数 / 单操作数 / 无操作数指令数量约束，求还能设计多少条指令。
- 说明为什么要采用扩展操作码，或按字段设计指令格式。
- 利用 Huffman 编码法对给定操作码频率进行编码，并计算平均码长。
- 比较等长码、Huffman 码、两种码长的扩展操作码三种编码方式的平均码长。
- 给定指令格式，判断是否可以进行扩展操作码编码（如把单地址指令条数改为极限值后是否仍可行）。

## 主考点

- **指令字中操作码与地址码的位数分配**：定长格式下，双操作数指令操作码 = 指令字长 − 2 × 地址字段位数；单操作数指令操作码 = 指令字长 − 1 × 地址字段位数。
- **扩展操作码逐层"让位"的思路**：
  - 双操作数指令的操作码高位中，未被双操作数指令用完的编码，作为"扩展前缀"留给单操作数指令。
  - 单操作数指令的操作码再从中未用完的编码，继续让位给无操作数指令。
  - 每层至少保留 1 种编码用于扩展标志（不是所有编码都可以分配给本层指令）。
- **Huffman 编码**：根据指令使用频率构建二叉树，高频指令码长短、低频指令码长长，平均码长 = Σ(频度 × 码长)。
- **三种编码的平均码长对比**：等长码 ≥ 扩展操作码 ≥ Huffman 码（平均码长从大到小）。扩展操作码是 Huffman 码的实际可行近似。

## 常用解题骨架

1. **按题意写清每类指令占用几个地址字段**：双操作数指令占 2 个地址字段，单操作数指令占 1 个，无操作数指令占 0 个。
2. **算操作码实际可用位数**：
   ```
   双操作数指令操作码位数 = 指令字长 − 2 × 地址字段位数
   单操作数指令操作码位数 = 指令字长 − 1 × 地址字段位数
   无操作数指令操作码位数 = 指令字长
   ```
3. **按扩展规则逐层分配**：
   ```
   双操作数指令最多可有 2^(双操作码位数) 种编码。
   已用 M 条，则剩余 2^(双操作码位数) − M 种作为扩展前缀。
   每种扩展前缀 × 2^(地址字段位数) 种编码供单操作数指令使用。
   单操作数指令最多可有 (2^(双操作码位数) − M) × 2^(地址字段位数) 条。
   已用 K 条单操作数指令，则继续向下扩展给无操作数指令。
   ```
4. **Huffman 编码题**：先建 Huffman 树（每次合并频度最小的两个节点），再从根到叶分配 0/1，最后算平均码长。
5. **三种编码方式对比题**：分别算出等长码（⌈log₂(总指令数)⌉位）、Huffman 码（平均码长）、扩展操作码（平均码长），列表对比。

## 建议作答模板

### 类型一：扩展操作码求指令条数

1. **先写每类指令各占多少个地址字段**：
   ```
   双操作数指令：占 2 个地址字段 → 操作码位数 = W − 2×A
   单操作数指令：占 1 个地址字段 → 操作码位数 = W − A
   无操作数指令：占 0 个地址字段 → 操作码位数 = W
   ```
   其中 W 为指令字长，A 为每个地址字段位数。

2. **逐层算扩展空间**：
   ```
   双操作数指令最多 2^(W−2A) 种编码，已用 M 条。
   剩余 2^(W−2A) − M 种编码作为扩展前缀。
   每种前缀可扩展出 2^A 种编码。
   → 单操作数指令最多 (2^(W−2A) − M) × 2^A 条。
   已用 K 条单操作数指令，则继续扩展给无操作数指令。
   ```

3. **注意空指令**：如果题目要求含"空指令"或"无操作指令"的条数，需要在最终分配时预留或计入。

### 类型二：Huffman 编码

1. **建 Huffman 树**：每次合并频度最小的两个节点，直到只剩一个根节点。
2. **从根到叶分配 0/1**：左子树赋 0、右子树赋 1（或反过来，但必须一致）。
3. **算平均码长**：`平均码长 = Σ(频度ᵢ × 码长ᵢ)`。
4. **与等长码、扩展操作码对比**：等长码码长 = ⌈log₂(指令总数)⌉，扩展操作码码长介于两者之间。

### 类型三：综合设计题

1. 先按题意分类统计各指令数量或频度。
2. 若要求 Huffman 编码：建树、编码、算平均码长。
3. 若要求扩展操作码：按频度从高到低分配码长，高频指令用短码、低频指令用长码，每层至少保留 1 种编码用于扩展。
4. 算平均码长并与等长码对比，说明扩展操作码相对于等长码的节省比例。

## 易错点

- **不区分单操作数和双操作数对地址字段的占用差异**：双操作数指令占 2 个地址字段，操作码位数少；单操作数指令占 1 个，操作码位数多。两者操作码位数不同，不能混用。
- **只算总编码空间，不按扩展操作码层次分配**：错误做法是把所有层的编码空间直接相加。正确做法是逐层"让位"：上层未用完的编码才向下层扩展。
- **忘记每层至少保留 1 种编码用于扩展标志**：扩展操作码的关键约束是：若本层需要继续向下扩展，则不能把所有编码都分配给本层指令，至少要留 1 种作为"扩展前缀"。
- **Huffman 树合并方向不一致**：从根到叶分配 0/1 时，必须统一规则（如左 0 右 1），否则不同同学的答案可能码字不同但平均码长相同。
- **把"空指令"条数遗忘**：`2020_final` 在标准扩展操作码题基础上加了"空指令条数"约束，如果忽略这个条件会直接算错。
- **求极限值时忘记下层约束**：题目问"最多还可设计多少条"时，需要同时考虑本层编码空间和下层已占用的编码（下层已用 N 条无操作数指令，占用了扩展空间，限制了本层可用的前缀数量）。
- **Huffman 编码和扩展操作码的关系不清**：扩展操作码是 Huffman 编码的一种实际工程近似——把 Huffman 树中相邻的码长合并成少数几种固定码长，牺牲少量平均码长换取译码器的规整性。
